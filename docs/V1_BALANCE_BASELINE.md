# V1 Balance Baseline

Generated by `apps/sim-cli` (Task 16 release gate) against the engine at commit
`0b8d100` (master, post-freeze-fix). Every number below is measured from a real
seeded simulation, not hand-tuned.

## Command

```bash
pnpm --filter @ai-lab-tycoon/sim-cli sim -- --runs 10 --seed 42 --max-weeks 120
```

Determinism is confirmed by the CLI: the same seed/runs invocation reproduces an
identical final state (the CLI asserts this on every run).

## Checkpoint (10 runs, seed 42, max 120 weeks)

| Metric | Value |
|---|---|
| Multimodal milestone reach | 1/10 (10%) |
| Milestone reach by bot | efficiency-first 1/10 (10%); others 0/10 |
| Milestone week | p50 = 63 |
| Continued additional weeks after milestone | 58 |
| Loss causes | cash_depleted 28, trust_collapsed 0, active-at-horizon 12 |
| First launch week | p50 = 5 |
| Terminal week (losses) | p10=4 p50=5 p90=6 |
| Compute shortage | runs with shortage 12, avg 33.4 shortage-weeks, peak p90 = 230 |
| Rival lead changes | 12 avg 0.3/run |
| Funding | seed 12/12 accepted, series_a 1/1 accepted |
| Foundations | fresh 33, continued 4, distilled 3 |

## Interpretation

- **A coherent bot reaches and continues past the multimodal milestone**:
  `efficiency-first` launched first product week 5, reached the multimodal
  milestone at week 63, and kept playing 58 more weeks without loss. This
  satisfies the Task 16 acceptance that at least one coherent bot reach the
  milestone and continue.
- **The frontier is slow and only one archetype reliably survives it.** The
  other three bots (random, capability-rusher, evaluator) go bankrupt by week
  4-7. Root cause: they spend cash faster than the early economy recovers —
  designing a model (80-280), buying compute (300), and hiring (300) inside the
  first handful of weeks while upkeep (75/week) and launch costs outrun the
  single-product revenue ramp. Only `efficiency-first` (which conserves cash and
  defers expansion) survives.
- **`cash_depleted` dominates and `trust_collapsed` never fires.** This is the
  plan's "no single accidental loss condition should dominate" red flag. The
  early game is bankruptcy-heavy and the trust-collapse loss path is
  effectively unreachable for these bots.
- **Severe, sustained compute shortage** (avg 33 shortage-weeks) after launch:
  product serving demand outgrows the fixed 12 starting capacity until the bot
  buys compute; the shortage-driven incidents dominate later play.

## Deferred tuning (plan Task 16 note)

The plan explicitly defers numerical balance tuning until after mechanics are
correct. The structural fixes are in place (compute purchase, team hiring,
product resume, infrastructure capacity gain). Recommended next tuning pass,
against `apps/sim-cli` with the same harness:

1. Slow early cash burn: re-check model design + foundation costs and opening
   upkeep so a non-conservative bot survives past week 8.
2. Make `trust_collapsed` reachable by a coherent bot (e.g. low-quality scandal
   paths) so both terminal rules are exercised.
3. Reduce post-launch compute-shortage severity so a single product does not
   accumulate hundreds of shortage-weeks.
4. Bring milestone timing down from ~week 63 toward the 30-60 minute session
   target.

Re-run this checkpoint with 50 runs once the tuning lands; the CLI accepts
`--runs 50`.
